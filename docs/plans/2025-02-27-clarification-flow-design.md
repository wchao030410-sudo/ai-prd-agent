# PRD 生成澄清流程设计文档

**日期**: 2025-02-27
**作者**: AI PRD Agent Team
**状态**: 设计完成，待实施

---

## 1. 问题背景

用户在 PRD 生成页面的初始输入往往过于模糊（如"做一个外卖App"），导致生成的 PRD 质量不高。

**当前问题**：
- 只有一个简单的 5 行文本框
- 用户输入后直接生成 PRD，缺少引导和上下文收集
- 缺少对输入质量的判断和反馈

---

## 2. 设计方案：混合模式 + AI 智能澄清

### 2.1 核心原则

1. **混合模式**：简单输入框 + AI 检测模糊时提出问题
2. **聊天式插入**：在输入框下方以对话气泡形式逐一提问
3. **AI 自主判断**：让 AI 判断输入是否充分
4. **实时预览**：每回答一个问题就在侧边显示"产品画像"

### 2.2 整体流程图

```
用户输入产品想法
        ↓
    [AI 判断清晰度]
        ↓
   ┌────┴────┐
   ↓         ↓
清晰     不清晰
   ↓         ↓
直接生成   聊天式提问(2-4个动态问题)
   ↓         ↓
         侧边实时预览"产品画像"
   ↓         ↓
         回答完成 → 生成 PRD
```

---

## 3. 澄清对话交互设计

### 3.1 触发条件

- 后端 AI 判断输入质量 `confidence < 0.6` 时触发

### 3.2 交互流程

```
用户点击"生成 PRD"
        ↓
    [AI 分析输入]
        ↓
  输入不清晰？
        ↓ 是
显示对话气泡："关于你的产品，我想确认几个细节..."
        ↓
逐一提问（2-4个问题，AI动态生成）：
        ↓
  Q1: [问题]
      [选项/示例]
      [用户输入回答]
      → 答案实时同步到右侧"产品画像"预览
        ↓
  Q2: [问题]
      ...
        ↓
显示"准备就绪"按钮 → 点击后生成 PRD
```

### 3.3 问题展示格式

每个澄清问题包含：

**Choice 类型**（带选项）:
```
┌─────────────────────────────────────────────────┐
│  💬 Q1: 主要面向哪类用户？                      │
│                                                  │
│  □ 程序员/开发者                                 │
│  □ 内容创作者/作家                               │
│  □ 产品经理/运营                                 │
│  □ 企业管理者/决策者                             │
│                                                  │
│  或者自定义：_______________________              │
└─────────────────────────────────────────────────┘
```

**Example 类型**（带示例）:
```
┌─────────────────────────────────────────────────┐
│  💬 Q2: 和现有产品相比，你的核心特色是？         │
│                                                  │
│  💡 示例：                                       │
│  • "专注于中文写作场景"                          │
│  • "集成了代码审查功能"                          │
│                                                  │
│  你的回答：____________________________________   │
└─────────────────────────────────────────────────┘
```

### 3.4 AI 动态问题生成策略

- **优先级**：目标用户 > 核心功能 > 使用场景 > 竞品差异
- **问题数量**：2-4 个，由 AI 根据输入质量决定
- **类型分配**：
  - `choice`: 带具体选项的问题
  - `example`: 带真实产品示例的问题
  - `open`: 开放式问题（慎用）

## 5. 后端 API 设计

### 5.1 新增 API：输入质量分析

```
POST /api/prd/analyze-input
```

**请求**:
```json
{
  "idea": "做一个外卖 App"
}
```

**响应**:
```json
{
  "isClear": false,
  "confidence": 0.3,
  "clarifyingQuestions": [
    {
      "id": "q1",
      "question": "主要面向哪类用户？",
      "type": "choice",
      "options": ["程序员/开发者", "内容创作者", "企业管理者"],
      "examples": ["面向大城市的上班族", "专注校园市场"]
    },
    {
      "id": "q2",
      "question": "和美团、饿了么相比，你的核心差异是？",
      "type": "example",
      "examples": ["专注某一品类的垂直配送", "更便宜的会员订阅模式"]
    }
  ]
}
```

### 5.2 修改 API：PRD 生成

```
POST /api/prd/generate
```

**请求（新增字段）**:
```json
{
  "idea": "做一个外卖 App",
  "clarifications": [
    { "question": "主要面向哪类用户？", "answer": "程序员群体" },
    { "question": "核心差异是？", "answer": "专注夜间配送" }
  ]
}
```

**Prompt 增强**:
```typescript
const enhancedPrompt = `
用户原始想法：${idea}

用户补充信息：
${clarifications.map(c => `- ${c.question}: ${c.answer}`).join('\n')}

请基于以上完整信息生成 PRD...
`;
```

## 6. Prompt 工程设计

### 6.1 输入分析 Prompt

**新增文件**: `lib/prompts/clarification-prompt.ts`

```typescript
export const INPUT_ANALYSIS_PROMPT = (idea: string) => `
你是一位资深产品经理，需要分析用户的产品想法是否足够清晰。

# 用户输入
"${idea}"

# 任务
1. 判断输入清晰度（0-1 分）
2. 如果清晰度 < 0.6，生成 2-4 个澄清问题

# 澄清问题要求
- 优先级：目标用户 > 核心功能 > 使用场景 > 竞品差异
- 每个问题必须包含：
  * type: "choice" | "example" | "open"
  * options: 3-4 个具体选项（choice 类型）
  * examples: 1-2 个真实产品示例（example 类型）
- 问题要具体，避免抽象
- 从用户痛点出发，而非技术实现

# 输出格式（JSON）
\`\`\`json
{
  "isClear": false,
  "confidence": 0.4,
  "clarifyingQuestions": [...]
}
\`\`\`
`;
```

## 7. 类型定义

**新增类型** (`types/prd.ts`):

```typescript
export interface ClarificationQuestion {
  id: string;
  question: string;
  type: 'choice' | 'example' | 'open';
  options?: string[];
  examples?: string[];
}

export interface ClarificationAnswer {
  question: string;
  answer: string;
  skipped?: boolean;
}

export interface InputAnalysisResult {
  isClear: boolean;
  confidence: number;
  clarifyingQuestions: ClarificationQuestion[];
}
```

## 8. 边界情况处理

| 场景 | 处理方式 |
|------|----------|
| 用户跳过某问题 | 允许跳过，该问题标记为 `[已跳过]`，PRD 生成时说明"此信息未提供" |
| AI 返回无效 JSON | 降级为直接生成 PRD，显示"输入分析失败，直接生成中..." |
| 用户中途取消 | 保存已回答内容，下次可继续 |
| 输入少于 10 字 | 直接拒绝，提示"请输入至少 10 个字符" |
| AI 判断清晰但用户仍想优化 | 显示"想获得更好的结果？点击优化"按钮 |
